# Quick Response 设计规格

日期：2026-05-28

## 目标

把 Watch 端结束录音后的第一屏回应做成完整体验的核心：不是摘要，不是泛泛安慰，而是一句基于用户真实内容、带有经文智慧、极短但有分量的回应。

这一阶段先不继续推进 realtime。先保证普通完整链路返回的 Quick Response 足够好，让用户日常使用时已经能获得完整体验。

## 产品定位

Quick Response 是「属灵辨明的一屏回应」。

它的任务是：

- 听懂用户此刻是在祷告、回转、自省、焦虑、怒气、悔改、饶恕、交托，还是在记录灵感、待办、普通问题。
- 对适合经文回应的内容，给出一句经文真理下的回应。
- 对不适合经文回应的内容，不强行属灵化。
- Watch 上一眼读完，iPhone 里保留完整整理。

## 适合经文回应的类型

优先使用经文型回应：

- 回转：怒气、被冒犯、论断、想反击、想证明自己。
- 祷告：交托、寻求、感谢、代祷、呼求。
- 自省：认罪、羞愧、悔改、软弱、控制感。
- 情绪：焦虑、惧怕、压力、委屈。
- 关系：饶恕、和好、忍耐、慢慢说话。

不默认使用经文型回应：

- 灵感、创意、产品想法、文章想法。
- 待办、提醒、生活记录。
- 普通 AI 问答。
- 信息不明确的短记录。

这些类型可以保存、分类、给下一步，但不要硬套经文。

## Watch Response 结构

继续使用现有字段，但重新定义内容责任：

### `eyebrow`

4-8 字，说明属灵处境或回应姿态。

示例：

- `先回到神前`
- `把心交托`
- `慢慢地说`
- `回到恩典`

### `headline`

2-6 字，一屏里最核心的大字。必须像锚点，不写完整句子。

示例：

- `先交托`
- `慢慢地说`
- `回到恩典`
- `不要抓住`
- `祂仍掌权`

### `body`

12-28 个汉字，一句核心回应。它要把用户刚才的内容带回一个经文真理，但不要讲道。

示例：

- `把忧虑带到神面前，不必先靠自己撑住。`
- `先让神掌管舌头，再决定是否回应。`
- `承认罪，也领受祂真实的赦免。`
- `把方向交给主，不急着靠聪明抓答案。`

### `footnote`

经文出处或简短状态。经文型回应必须给出处。

示例：

- `腓 4:6`
- `雅 1:19`
- `约一 1:9`
- `箴 3:5`

## 语气规则

必须：

- 温柔、清醒、有属灵分量。
- 像陪伴用户回到神面前。
- 具体回应用户刚才的内容。
- 短到 Watch 上能一眼读完。

禁止：

- 泛泛鸡汤。
- 讲道式长解释。
- 审判、控告、定罪用户。
- 滥用“你应该”。
- 编造经文或出处。
- 每条记录都硬塞经文。
- 把 Watch 回应写成摘要。

## 经文引用规则

只引用高确定性的经文或经文原则。

如果不能确定具体章节：

- 不写伪造出处。
- 可以使用经文原则型回应。
- `footnote` 可以写 `完整内容已保存`，完整分析里再谨慎补充。

第一阶段建议使用小型高置信经文池，避免模型乱引：

- 焦虑/交托：腓 4:6，太 6:34。
- 怒气/言语：雅 1:19，箴 15:1。
- 认罪/赦免：约一 1:9，罗 8:1。
- 信靠/决定：箴 3:5-6。
- 软弱/恩典：林后 12:9。
- 惧怕：提后 1:7，诗 56:3。
- 忍耐/爱：林前 13:4-7。

```json
  "headline": "先交托",

  "footnote": "腓 4:6"
}
```

## 实现边界

本设计阶段不改变 UI 结构，不推进 realtime。

实现阶段只应改：

- 服务端 `analyzeQuickWatchResponse()` prompt。
- realtime quick instructions 的同款规则。
- 必要的 schema 描述。
- 小型经文回应样例和测试脚本。

不应改：

- Watch 录音状态机。
- iPhone 列表结构。
- Supabase 表结构，除非为了保存额外诊断字段。

## 验收标准

1. 回转/祷告/自省类输入，Watch 回应明显比现在更有经文智慧。
2. Watch 回应不超过一屏，不卡布局。
3. 不适合经文的输入不会被强行属灵化。
4. 至少覆盖焦虑、怒气、认罪、交托、祷告、灵感、待办、普通问题 8 类样例。
5. 模型不得编造经文出处。
6. iPhone 完整详情仍保留更完整的整理，不被 Quick Response 限制。
